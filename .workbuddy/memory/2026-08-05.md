5. **project/enemys.js** - 给7个代表性敌人添加示例属性：greenSlime(burn:1), bat(ice:1), skeletonCaptain(cleanse:true), redWizard(dispel:1,darkness:1), darkKnight(exhaustion:2), magicDragon(attackInterval:1.5,hitRate:0.8,burn:3), vampire(block:5,regeneration:2)。

6. **tests/backpackBattle.test.js** - 新增5个测试（#35-#39），覆盖敌人 afterHit 施加烧伤、净化、驱散、自身Buff和预计模拟同步。全部39测试通过。

7. **武器布局联动与战斗触发规则说明.md** - 新增"七、敌人战斗属性配置"章节。

### 设计要点
- 敌人 `afterHit` 中 `target: "opponent"` 指向玩家，`target: "self"` 指向敌人自身。
- 敌人不支持 `triggerWeaponAttack` 和 `triggerLinkedWeaponAttack`（无背包武器）。
- 简化字段和自定义 `combatRules` 可合并使用。
- 敌人没有 `combatRules` 时行为与修改前完全一致，不影响现有随机序列。

## 战斗状态图标加载修复

### 问题根因
`renderStatuses` 每次渲染执行 `container.innerHTML = ""` 销毁全部图标 DOM，再重建所有 `<img>`。战斗每帧（~60fps）触发 `notify()` → `render`，`<img>` 异步加载在下一帧到来前（16ms）来不及完成就被清空，导致图标永远空白；加载失败时浏览器显示破损问号图标。无预加载、无 onerror 兜底。

### 修复内容
1. **project/backpackBattleUI.js**：
   - 新增 `preloadStatusIcons()`，战斗面板 `build()` 时预加载全部 10 个状态 SVG。
   - 重写 `renderStatuses`：按 `sideKey + statusId` 缓存图标节点（`statusIconNodes`），已存在图标只更新层数/CD/aria-label；新状态才创建节点，移除状态才删除。
   - tooltip provider 改为从 `latestSnapshot` 动态读取当前层数（节点复用后不能依赖闭包旧值）。
   - 新增 fallback 元素（状态名首字），`img.onerror` 时隐藏 img 显示首字。
   - `close()` 清空 `statusIconNodes`。
2. **project/backpack.css**：新增 `.bb-status-fallback` 样式（含移动端 22px 适配）。
3. **tests/backpackBattle.test.js**：新增回归测试 #40 锁定修复（静态断言：无 innerHTML 清空、有节点缓存、有预加载、有 error 兜底）。全部 40 测试通过。

### 经验
高频渲染下（每帧重建 DOM）不要用 `innerHTML=""` + 重建 `<img>` 的方式更新图标；应缓存 DOM 节点复用，图片只需加载一次；首次使用前预加载图片；加载失败提供文字兜底。

### 修正：改为 canvas 绘制原图标（用户要求）
用户反馈不要文字兜底，要求仍显示原 SVG 图片，改用 canvas 绘制。
- `project/backpackBattleUI.js`：新增 `statusImages` 图片缓存 + `getStatusImage`（同一 SVG 只加载一次）；新增 `drawStatusIcon`（`ctx.drawImage` 绘制到 52x52 canvas，图片未加载完成时注册 onload 通过 `redrawStatusIcons` 补绘）；`renderStatuses` 中图标由 `<img>` + 文字 fallback 改为 `<canvas class="bb-status-canvas">`；`preloadStatusIcons` 复用图片缓存。
- `project/backpack.css`：`.bb-status img` / `.bb-status-fallback` 替换为 `.bb-status-canvas`（26px，移动端 22px）。
- 测试 #40 更新为断言 canvas 绘制（drawImage、statusImages、bb-status-canvas）。
- 教训：用户明确要求"用 canvas 绘制原来的图标"时，不要自作主张加文字 fallback；SVG 需经 Image 对象加载后 drawImage 到 canvas，加载完成前先注册补绘。
