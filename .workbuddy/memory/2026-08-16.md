
## sameNameCount/sameNameDamageBonus 支持 groupBy 武器类型
- 需求：规则填在 a 武器，一把 a + 三把 b（b 与 a 同 weaponType）也触发（不再只看同名）。
- 实现（backpackBattleRules.js）：
  - 新增 countGroupedWeapons(state, weapon, groupBy)：groupBy==="weaponTypes" 时统计与当前武器共享任意 weaponType 的武器数（含自身）；否则同名计数（原行为）。
  - sameNameCount 条件：改用 countGroupedWeapons(condition.groupBy)。
  - sameNameDamageBonus：bonus 注册带 groupBy；getSameNameDamageBonus 用 bonus.groupBy 计数。
- 配置示例：条件/效果加 "groupBy": "weaponTypes"。
- 验证：1把A盾+3把B盾(同"盾")→ block×5 触发 ✓（日志"勇士获得格挡 ×5"）；默认同名行为不变。
- version 2.10.48。

## sameNameCount 语义修正：任意同名武器组
- 用户澄清：不需要同类型，要的是"场上任意 3 把相同武器就触发 a 的效果"（与 a 同名与否无关）。
- 修改 countGroupedWeapons 默认分支：统计场上"任意同名武器组"的最大数量（不再要求与当前武器同名）；groupBy: weaponTypes 分支保留。
- 验证：A×1+同名B×3 触发✓；同名A×3 触发✓；4把全不同名不触发✓。89 项测试全过。version 2.10.49。

## sameNameDamageBonus 归属修正 + 测试更新
- 新语义下 sameNameDamageBonus 加成只属于注册该效果的武器（sourceWeaponId 限定），触发判定用"任意同名组最大数量"。
- 更新测试 #78 场景4：伤害 55 → 45（A1 15 + A2/A3/B1 各10；加成不再扩散给同名组其他武器）。

## 商店/赠予选择器：控制锁 + 录像
- 需求：商店与随机武器道具（赠予选择器）打开时 core.lockControl 防误操作、关闭时解锁；购买/选择结果进录像。
- 实现（backpackShop.js）：
  - 打开（openShop/openRewardPicker）记录 shopWasLocked（打开前锁定状态）并 core.lockControl()；closeShop 仅当 shopWasLocked 为 false 时 core.unlockControl()（避免误解锁剧情等锁定）。
  - pushBackpackReplay()：core.status.route 存在时 push "backpack:" + 背包快照（复用背包系统注册的回放行为，回放时恢复含新武器的背包状态）；buyWeapon 成功与赠予选择器 pick 成功后调用。
- version 2.10.51。

## 商店/选择器：回放跳过UI + 锁定强化
- 问题1：录像回放时商店/选择器 UI 会挡住回放且无法关闭。
  - 修复：openShop/openRewardPicker 开头 isReplayingNow()（core.isReplaying 或 status.replay.route）→ 直接 return 不创建 UI；结果由录像中 "backpack:" 快照恢复。
- 问题2：打开时仍可操作（锁定无效——事件流程可能误解锁）。
  - 修复：lockShopControls() 直接置 core.status.lockControl=true + core.lockControl() + setInterval(100ms) 持续强制锁定（root 存在期间）；closeShop clearInterval 并按 shopWasLocked 恢复。
  - openShop 随机池为空时先 closeShop 清理锁定再 return。
- version 2.10.52。

## 修复：商店关闭后操作仍被锁
- 根因：closeShop 按 shopWasLocked（打开前锁定状态）决定是否解锁——若打开前恰好锁定（如事件中打开），关闭时条件跳过解锁 → 锁残留。
- 修复：closeShop 无条件解锁（core.status.lockControl=false + core.unlockControl）；移除 shopWasLocked 机制（商店是玩家主动打开，不应残留锁）。
- version 2.10.53。
