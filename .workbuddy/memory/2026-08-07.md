## 录像支持背包状态恢复

### 需求
录像中不能整理背包，但关闭背包时应把关闭时的背包状态写入录像，否则录像播放时与游戏进程不一致（整理后的布局影响战斗）。

### 实现（project/backpackSystem.js）
1. `openBackpack` 成功时记录 `openedStateSignature`（placed 位置/旋转 + inventory id + unlockedCells 的紧凑签名）。
2. `closeBackpack` 清理 DOM 后：若背包打开过、签名与打开前不同、非回放、游戏中且有 route，则 push `"backpack:" + encodeBackpackPayload()` 到 `core.status.route`。
3. `encodeBackpackPayload`：序列化 placed/inventory/unlockedCells（完整 weapon 定义），`encodeURIComponent(JSON.stringify(...))` 后再转义裸括号 `(` `)` 为 `%28`/`%29` —— 因为 `decodeRoute` 对 `(action)` 按第一个 `)` 截断还原，裸括号会破坏解析。
4. 导出 `restoreBackpackState(snapshot)`：readState 后重建 placed/inventory（normalizeEntry 自动用最新中央定义迁移），非法占位送回库存，persistState。
5. 安装时 `core.control.registerReplayAction("backpack", handler)`：解析 payload → restoreBackpackState → `route.push(action)`（保持录像一致性校验）→ `core.replay()` 继续；非 backpack: 前缀返回 false 不误吞其他动作。

### 关键点
- 录像机制：route 数组记录动作，`registerReplayAction(name, func)` 注册回放处理（func 返回 true 表示处理），`encodeRoute` 把未知动作包成 `(动作)`，`decodeRoute` 原样还原。
- 打开未整理（签名相同）不写入，避免冗余；回放中 openBackpack 已被禁止，故动作只在录制阶段产生。
- 端到端验证：添加武器→编码→清空→恢复，placed/inventory/unlockedCells 完全一致；handler 恢复 + route 记录 + 继续回放正确；未知动作返回 false。
- 新增测试 #44（编码/恢复往返 + 静态断言），全部 44 项通过。

### 经验
- `core.status.route` 的 encodeRoute 会把未知动作用 `( ... )` 包裹，decodeRoute 按第一个 `)` 还原；自定义录像动作的序列化内容必须转义括号（或用 URL 编码 + 括号转义）。
- 背包系统可通过 `core.plugin.weaponSystem` 访问武器系统；在测试中需先安装武器系统再安装背包系统。

## 修复：录像中战斗结束后停住

### 症状
播录像时每次打完怪都停住，手动"暂停+继续"（实际是触发 resumeReplay）才继续。

### 根因
录像中移动触发战斗的路径：`_moveAction_noPass` → `core.trigger(x,y)` → 怪物块无显式 event 数组时走 `doSystemEvent("battle")` → `_sys_battle` → `events.battle(...)`（callback 为 undefined）→ 背包乱斗 `startBattle` 保存 `context.callback = undefined`。战斗结束 `settleFinishedBattle` 只调用 `if (context.callback) context.callback()`（undefined 被跳过）——**没有事件流结束回调来调用 `core.replay()`**，录像停住。手动暂停/继续恰好触发 replay 恢复。

### 修复（project/backpackBattle.js）
`settleFinishedBattle` 末尾 callback 分支改为：
```javascript
if (context.callback) {
    context.callback();
} else if (core.isReplaying && core.isReplaying() && typeof core.replay === "function") {
    core.replay();
}
```
- 事件流路径（callback=core.doAction）：仍由事件流结束统一 replay，不重复调用。
- 非录像：isReplaying=false，不调用，正常自动寻路。

### 验证
- 三场景模拟：callback 缺失→replay 调用 ✓；事件流路径→doAction 调用且 replay 不重复 ✓；非录像→不调用 ✓。
- 新增测试 #45（静态断言），全部 45 项通过。

### 经验
- 录像中战斗有两种触发路径：显式 `block.event.event`（走事件流，事件流结束自动 replay）和 `doSystemEvent("battle")`（直接 battle，无事件流，无结束回调）。任何"无事件流"的异步操作结束后，若处于录像播放中，需手动调用 `core.replay()`。
- 排查录像停住问题：先判断战斗是否经过事件流（context.callback 是否存在），再检查事件流结束回调链。

## 诊断：呪蚀之骸枪 combatRules 不生效（只读诊断，未改文件）
- weapons.js 中 combatRules 存在两种格式：数组（正常，如 薛定谔/精灵火龙/精灵欧罗巴）和**对象**（{id,trigger,conditions,effects}，如 I386 呪蚀之骸枪、I388 塞勒斯特之镰·玛格纳）。
- `runCombatRules` 只接受数组：`Array.isArray(weapon.combatRules) ? weapon.combatRules : []`；对象 → 空数组 → 效果全部静默忽略。`backpackBattle.js` 战斗快照 `clone(entry.weapon.combatRules || [])` 原样克隆，不做归一化。
- 实测：对象格式 → 虚脱0/无debuff；同一效果改数组 → 虚脱2+ice。修复方向：weapons.js 改为数组（`"combatRules": [{...}]`）或在快照构建时归一化对象为数组。
